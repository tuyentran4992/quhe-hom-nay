## 4. `hexagrams` — 64 quẻ, seed từ `backend/database/data/hexagrams.json`

```sql
CREATE TABLE hexagrams (
  id           TINYINT UNSIGNED NOT NULL,            -- 1..64, thứ tự Văn Vương, KHÔNG auto-inc
  han          VARCHAR(4)       NOT NULL,            -- Hán tự tên quẻ (1–2 ký tự)
  ten          VARCHAR(40)      NOT NULL,            -- "Càn Vi Thiên"
  quoc_am      VARCHAR(20)      NOT NULL,
  upper        VARCHAR(10)      NOT NULL,            -- quái Thượng (vocab đúng 8 quái)
  lower        VARCHAR(10)      NOT NULL,            -- quái Hạ
  `lines`      JSON             NOT NULL,            -- [0|1 x6] từ DƯỚI lên TRÊN (kiểm định 64/64 khớp lower-first). LƯU Ý: `lines` là từ khóa dành riêng MariaDB — BẮT BUỘC backtick trong migration raw SQL; model Eloquent dùng fillable 'lines' bình thường
  symbol       VARCHAR(4)       NOT NULL,            -- ䷀ U+4DC0..U+4DFF
  dai_ci       TEXT             NOT NULL,            -- 大意, 55–87 ký tự
  free_content JSON             NOT NULL,            -- {congViec,tinhDuyen,taiLoc}, mỗi slot ≤45 từ (CUT-45: 0/192 vi phạm)
  keywords     JSON             NOT NULL,            -- đúng 4 phần tử
  vv_nien      VARCHAR(200)     NOT NULL,            -- Vận niên
  cat          JSON             NOT NULL,            -- ["tot"|"xau"|"trung"], 1 phần tử (thực tế seed: 63 trung, 1 tot)
  ban_goc      JSON             NOT NULL,            -- {quaTu,thoanTruyen,tuongTruyen,haoTu[,dungHao — chỉ id 1,2]}
  luan_nay     TEXT             NOT NULL,            -- luận ngày, 136–425 từ
  created_at   TIMESTAMP NULL,
  updated_at   TIMESTAMP NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_hexagrams_ten (ten)

```

**Quyết định kiến trúc (dev-lead chốt, ADR-001 tại /data/agents/dev-lead/adr/): BẢNG RIÊNG,
không phải cột JSON trong `hexagrams`.** Trade-off:
- Bảng riêng: ✓ verify "384 ô không rỗng" bằng SQL đếm được, không cần parse JSON; ✓ seeder
  idempotent theo từng row `(hexagram_id, vi)` — sửa 1 hào không đụng 63 quẻ khác; ✓ dữ
  liệu từ hào do research giao incremental (part1..4) nên cập nhật độc lập với file seed
  `hexagrams.json` ĐÃ chốt sha256 (`76cfc11f…` — CẤM sửa file đó, chỉ thêm file mới);
  ✗ thêm 1 JOIN (chi phí 0 với 384 row, PK cluster).
- Cột JSON vào `hexagrams`: ✗ phá vỡ hợp đồng seed đã QA (U1/U2 assertion đếm theo
  hexagrams), ✗ không kiểm được từng hào thiếu ở đâu, ✗ mỗi lần research bổ sung là sửa
  nguyên mảng 64 object. → LOẠI.
- Dụng hào (quẻ 1 `用九`, quẻ 2 `用六`) KHÔNG vào bảng này — nó thuộc `ban_goc.dungHao`
  đã seed sẵn; bảng này đúng 384 row, không 386.

## 6. `payments` — đơn unlock chủ đề + donate ("Lễ tùy tâm")

```sql
CREATE TABLE payments (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_code      BIGINT UNSIGNED NOT NULL,          -- payOS order code: unix_ts*10 + 1 số ngẫu nhiên (9-15 chữ số)
  device_id       CHAR(26)        NOT NULL,
  user_id         BIGINT UNSIGNED NULL,
  kind            ENUM('unlock','donate') NOT NULL DEFAULT 'unlock',
  topic           ENUM('duyen','tai_loc','xuat_hanh') NULL,   -- NOT NULL khi kind=unlock (enforce ở service)
  amount_vnd      INT UNSIGNED    NOT NULL,          -- unlock: 29000 (C-05); donate: 1000–500000
  status          ENUM('pending','paid','cancelled','expired','refunded') NOT NULL DEFAULT 'pending',
  gateway_ref     VARCHAR(64)     NULL,              -- payOS paymentId / transactionRef từ webhook
  paid_at         TIMESTAMP       NULL,
  idempotency_key VARCHAR(64)     NOT NULL,          -- client sinh mỗi lần bấm CTA
  created_at      TIMESTAMP NULL,
  updated_at      TIMESTAMP NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_payments_order (order_code),
  UNIQUE KEY uq_payments_idem (idempotency_key),
  UNIQUE KEY uq_payments_entitlement (device_id, kind, topic), -- 1 device mua 1 chủ đề 1 lần (donate topic NULL → không chặn donate lặp; UNIQUE bỏ qua NULL)
  KEY idx_payments_status (status, created_at),
  CONSTRAINT fk_payments_device FOREIGN KEY (device_id) REFERENCES devices(device_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Entitlement = tồn tại row `device_id + kind='unlock' + topic + status='paid'`.
`refunded` (QA-THU-TIỀN hoàn 1kđ, hoặc hoàn chủ động) → mất entitlement.

## 7. `ai_jobs` — luận giải chuyên sâu, chạy qua queue DATABASE

```sql
CREATE TABLE ai_jobs (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  job_uuid      CHAR(36)        NOT NULL,            -- lộ ra API: GET /api/ai/jobs/{job_uuid}
  device_id     CHAR(26)        NOT NULL,
  draw_id       BIGINT UNSIGNED NOT NULL,
  topic         ENUM('duyen','tai_loc','xuat_hanh') NOT NULL,

  attempts      TINYINT UNSIGNED NOT NULL DEFAULT 0, -- tối đa 3 (C-04)
  result        MEDIUMTEXT      NULL,                -- markdown luận giải khi done
  error_code    VARCHAR(32)     NULL,                -- AI_TIMEOUT | AI_UPSTREAM | AI_FILTERED
  requested_at  TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP, -- tính cooldown C-03 + cap C-06
  finished_at   TIMESTAMP       NULL,
  created_at    TIMESTAMP NULL,
  updated_at    TIMESTAMP NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_ai_jobs_uuid (job_uuid),
  KEY idx_ai_jobs_device_time (device_id, requested_at),
  KEY idx_ai_jobs_status (status, requested_at),

  CONSTRAINT fk_ai_jobs_draw FOREIGN KEY (draw_id) REFERENCES draws(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 8. Device identity (chốt kiến trúc — BE-1/FE-1 làm đúng như này)

- Lần đầu tiên client gọi API (bất kỳ endpoint nào), middleware `EnsureDeviceSession`:
  không có cookie `qhn_device` → sinh `device_id` = 26 ký tự base32 CSPRNG → INSERT
  `devices` → set cookie `qhn_device` (HttpOnly, SameSite=Lax, Max-Age 400 ngày, path /).
- Mọi rule (1 quẻ/ngày, cooldown, cap, entitlement) khóa theo `device_id`, KHÔNG theo
  session Laravel — session hết hạn không được làm mất tiền đã trả.
